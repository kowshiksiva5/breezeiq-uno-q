AC synchronization

Compressor-aware cooling

AC power intent travels through Home Assistant. Compressor minimum-off time and command rate limits live at the board action boundary. When reported power is available, room-response modeling follows that state. Without readback, the UI shows the uncertainty.

Fan speed

Air movement before AC

The comfort ladder requests fan levels 0 through 3. The Atomberg adapter maps that intent to the verified device path and avoids spending vendor quota on unchanged state.

Light control

Occupancy plus light evidence

Automatic light intent requires presence and trustworthy darkness. LDR and camera luminance disagreement creates a hold instead of an unwanted switch.

Human authority

Manual control wins visibly

On the trusted room LAN, the dashboard needs no typed token. It sends confirmed manual requests to the running control process, where the same safety boundary handles automation and people.

One guarded path

The web UI has no direct vendor-control shortcut. A manual request cannot bypass compressor protection, command spacing, live-mode gates, or durable audit records.

Occupancy and light fusion

Two imperfect views, conservative decisions

Camera and PIR cover different failure modes. Camera luminance and LDR provide different views of room light.

PIR fallback

Motion extends presence

Recent motion prevents a quiet occupant from being treated as immediately absent. A quiet PIR cannot certify an empty room.

Camera boundary

Count only after valid inference

People count appears only when Linux sees a real camera and local inference returns a fresh valid result. Offline, stale, and failed remain explicit states. No raw frames are stored by default.

Light fusion

Disagreement becomes a hold

Calibrated LDR evidence and relative camera luminance combine locally. A large conflict, ADC rail clipping, or brightness that may come from the controlled lamp creates a hold.

Remember and recover

The board keeps the evidence

Control continues locally while maintenance and network backup run as separate bounded jobs.

Local database

Durable SQLite on eMMC

WAL mode and full synchronization protect committed records. Retention limits age and row count so telemetry cannot grow forever.

Integrity-first backup

Snapshot, hash, upload, verify

The board makes a consistent local snapshot, checks SQLite integrity, calculates SHA-256, uploads when Azure is configured, downloads a proof copy, and checks it again.

Offline queue

Network loss never blocks comfort

A failed cloud upload leaves the checked local snapshot queued for retry. Restore targets a fresh database and refuses an untrusted hash.
